# Domain docs

単一コンテキストとして、ルートの `GLOSSARY.md` と `docs/adr/` を使う。

## 調査・設計時

- コードを調べる前に `GLOSSARY.md` と、対象領域に関係するADRを読む。
- 将来 `GLOSSARY-MAP.md` が追加された場合は、そこから関係するコンテキストの用語集・ADRをたどる。
- 文書が未作成の場合は、そのまま調査を進める。用語・判断が確定した時点で `domain-modeling` により必要な文書を作る。
- Issue、設計案、コード、テストでは用語集の名称を使う。用語が曖昧な場合は定義を確認する。
- ADRと異なる案を出す場合は、対象ADRと見直す理由を明示する。

用語集には用語の定義を記載し、実装方針や未決事項は調査文書・仕様書・ADRに記録する。
