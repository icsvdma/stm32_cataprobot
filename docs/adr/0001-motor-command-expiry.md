# モーター指令の期限をSTM32で監視する

状態: 設計合意済み、未実装。2026-10-20。

SPI断やESP32停止でもSTM32は動作を続けるため、ESP32からの停止送信だけに依存せず、STM32が左右のモーター指令の期限を監視する。250 ms途絶えたら両輪の駆動出力を停止し、センサー要求やライト操作では期限を延長しない。センサー監視が正常なまま走行指令だけ停止する場合を検出するためである。左右の指令は1つのSPIコマンドで検証・採用し、片輪だけの更新を防ぐ。

起動・PS3再接続・通信復旧後は中立を300 ms連続で確認し、その後のSTART新規押下で走行を許可する。通信復旧だけで走行へ戻す方法より復帰操作は増えるが、以前の走行入力による再始動を防ぐ。□の新規押下による緊急停止とシャットダウンは電源再投入まで保持する。

STM32の制御更新は5 ms周期、最大更新間隔10 msを目標とし、指令期限250 msの経過後10 ms以内に駆動出力をゼロにする。これらは実機検証前の設計値であり、車体の停止時間を意味しない。電気的な停止特性は未確認。

ESP32とSTM32は対応する新ファームへ両方更新し、旧ファームとの混在では走行を許可しない。旧形式の速度指令を拒否し、停止・緊急停止は引き続き受理する。互換経路を維持する方法より更新の手間は増えるが、片輪ずつの更新や走行許可を通さない経路を残さないためである。

走行指令のACK欠落・NACK・不正応答を1回検出したら、ESP32も停止要求を送って再開待ちへ移る。WebにはSTM32の走行許可状態・停止理由を表示し、状態が取得できない場合は「通信不明」とする。

PS3切断も通常減速を待たず駆動出力ゼロ・再開待ちへの移行を要求し、再接続後は中立確認とSTART新規押下で再開できる。Hブリッジの型番・真理値表と、制動特性・停止距離の確認を実機走行の前提条件として残す。
